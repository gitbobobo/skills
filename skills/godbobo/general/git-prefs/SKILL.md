# git-prefs

## 提交

要求：

- 按可审计粒度提交，提交信息清晰、满足 Conventional Commits，且只提交应入库文件
- 核验修改内容相关的最小检查。已有证据与当前源码（含脏改动）、工具链及检查范围一致时，可读原始日志/报告、确认命令和退出码后采用；源码变化、证据不完整或覆盖有缺口时补跑对应检查。失败先修复，再完成提交
- 改动涉及 `skills/` 或 `README.md` 时（gitbobobo/skills 仓库），提交前确认 `node scripts/check.mjs` 在当前内容上通过；同源码的已有证据按上条核验采用

流程：

1. 先检查 `git status --porcelain` 再决策。
2. 若发现应忽略文件/临时文件：征求用户意见后决定 1 纳入提交 2 保留并更新 `.gitignore` 3 直接删除。
3. 按「提交要求」完成提交，结束时应尽量保证工作区干净。

## 同步

- 同步前确保工作区干净：先检查 `git status --porcelain`，若有未提交变更先按「提交」完成，再同步，避免 rebase / merge 时产生冲突或丢失改动
- 优先通过 rebase 保持线性历史
- 禁止直接丢弃提交内容，必须根据提交时间理解修改意图
- 冲突需先理解双方修改意图再解决，必要时征求用户意见

## 删除当前工作树（仅限用户明确要求）

「删除工作树」默认指当前所在的工作树：运行 `node <技能目录>/scripts/empty-worktree.mjs`（`--dry-run` 预演）。脚本清空当前链接工作树的全部内容（含 `.git`），保留目录壳并写入 `.worktree-placeholder`——目录留着，绑定它的终端 cwd 继续有效；随后在主仓库 `worktree prune` 注销注册。

- 绝不删除工作树目录本身（`rm -rf` 整树、`git worktree remove` 自己所在的树）：绑定该目录的终端在命令运行前即失败，永久失效，`cd` 救不回来
- cwd 必须是工作树根；在子目录时先 `cd` 到根再跑，否则清空会把终端 cwd 一起抹掉（脚本同样拒绝）
- 主检出（非链接工作树）一律拒绝执行，这是防呆底线
- 清空后该目录不再是 git 仓库，后续 `git` 命令失败是预期；空壳与本地分支留给后续清理
